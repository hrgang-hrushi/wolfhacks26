1. **Critical — Two speed trials accidentally become statewide fetches.** Step 2 specifies `--limit 500` only for the 32-worker run. In `chips.py`, `--seed` has no effect without `--limit`; the 64-worker run therefore fetches everything remaining, and the 128-worker run may do nothing. Specify `--limit 500` for all three trials and measure successfully fetched chips per second.

2. **Critical — The cloud job wrapper cannot reliably launch or resume.** Nothing creates `/root/hack/logs` before `run()` redirects output there. It also leaves previous `<name>.rc` files in place, so `wait()` can report an earlier run’s completion while the replacement is still running. Create the directory, use unique execution IDs, publish exit status atomically, and test reruns and failed launches.

3. **Critical — The spending limit is not enforced across failures or replacement boxes.** The watchdog permits proceeding without an autonomous stop, starts its timer after provisioning rather than at rental, and has no specified cleanup when provisioning fails. Several later gates simply “stop and report” while billing continues. Persist cumulative campaign spend, enforce the rental-time deadline independently of the Mac session, and define teardown or a bounded recovery path for every failure exit.

4. **Critical — Offer filtering does not require a suitable GPU.** The specified filter checks CPU, RAM, disk and CUDA compatibility, but no GPU model, count or VRAM. Selecting its first result does not establish that the planned batch sizes fit. Add explicit GPU requirements and a representative forward/backward memory check before the statewide fetch.

5. **Critical — The 32-sample training checks receive zero batches.** `batch_size=128` with `drop_last=True` drops the entire dataset in F9 and F15. Make batch size injectable for these tests, assert that optimizer steps occurred, and reject production folds whose training loader would be empty.

6. **Critical — The reduced experiment is ambiguous and cannot be expressed by the proposed command.** “Seed 1 on fold 0 only” must explicitly retain seed 0 across all five folds and all three arms; otherwise complete OOF comparisons disappear. `--seeds` alone cannot encode that schedule. Return and execute explicit `(arm, seed, fold)` jobs, and define seed spread using the matched fold-0 runs.

7. **Critical — The timing gate omits required work and the remaining deadline.** A training-epoch estimate does not establish the cost of model initialization, held-out evaluation, final eight-view inference, reporting and artifact transfer. `plan_grid()` also receives remaining dollars but not remaining rental time. Measure or conservatively budget these components and reserve time for verified pulls and teardown.

8. **Critical — Frozen and fine-tuned reports can overwrite each other.** Both runners write `metrics.json` and `report.md` under the same default output root. The final pull can replace the frozen comparison with the fine-tuned comparison. Define separate output directories and test that running both stages preserves both result sets.

9. **Critical — Resume validation does not establish that a run is complete or equivalent.** Matching code, table and road hashes does not cover epochs, configuration, shuffled-control status or model weights, nor prove that prediction files exist and are intact. Use a per-job completion manifest containing configuration and artifact checksums, written last; resume only after validating it.

10. **Critical — The table fingerprint omits inputs used by the frozen results.** `table_hash()` excludes `y_helene_failed` and `in_helene_zone`, although they determine flood fitting and scoring. Changing either could leave cached results apparently valid. Hash all consumed target, grouping and evaluation-mask columns, and test that changes invalidate reuse.

11. **Critical — NDVI coverage conflicts with AC9.** The frozen runner drops unusable roads before producing NDVI statistics, while AC9 requires one row per chipped road. Compute NDVI from every original valid chip before applying model exclusions, retaining blank-fraction and usability flags. Separately, Step 9’s `train_vit --frozen` writes `data/processed/vit_frozen.parquet` and uses a non-atomic copy, contradicting D11; explicitly resolve that exception or produce the compatible artifact through the permitted output writer.

12. **Suggestion — The array-ownership contract contradicts the planned implementation.** `np.ascontiguousarray()` can return the original array for view 0, so it does not guarantee owned, independent storage. A8 also conflicts with the explicit requirement that `NONE` return its input. Define ownership separately for transformation outputs and the `NONE` fast path, then align the implementation and tests.

13. **Suggestion — Sparse training subsets remain under-specified.** Returning NaN from metric functions does not prevent `StandardScaler`, `Ridge` or logistic regression from failing on empty training subsets. Specify handling for empty training/test folds, missing target labels and single-class binary training data; test that skipped predictions remain missing and are counted in reports.
