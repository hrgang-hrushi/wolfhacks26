1. **Critical — The regression command overwrites shared data.** Step 9 runs `pull_ncdot --join-only`, whose `main()` unconditionally writes `data/raw/ncdot_joined.parquet`. That directory is symlinked to shared storage, and this file is absent from the fingerprint checks. Run the join against cached inputs in memory or an isolated directory, and verify the shared raw input remains unchanged.

2. **Critical — Label generation never establishes `length_m`.** Step 4 loads only `seg_id`, `YEAR_LAST_REHAB` and geometry, but `build_labels` requires `length_m` for rates. The raw parquet does not contain that column. Explicitly calculate projected geometry length using the existing `features.py` convention, and test `main()` using the actual raw schema.

3. **Critical — Reports can fall beyond the exposure window.** Cleaning accepts dates up to `now + one day`, while label generation checks only `received_date >= start`. Consequently, tomorrow’s report can count against exposure ending today. Enforce `start <= received_date <= pulled_at` and test both endpoints.

4. **Critical — The collector loses its log when the circuit breaker trips.** Step 2 raises during the loop but writes `stills.parquet` only afterward. Earlier downloads become unlogged files, and failed attempts disappear, violating D17. Finalize placeholder handling and persist all attempted rows before propagating the stop condition. Extend K7 to verify the persisted log and filesystem state.

5. **Critical — Image filenames can overwrite previously recorded evidence.** Different image bytes with the same camera and `Last-Modified` timestamp bypass the SHA1 duplicate check but resolve to the same filename. Replacement changes evidence referenced by earlier manifest rows; subsequent placeholder deletion could remove it entirely. Define a collision policy that preserves existing evidence, and test changed bytes with an unchanged timestamp.

6. **Critical — Double grading lacks a defined identity reconciliation step.** Repeats receive new indices and files, but `agreement()` compares stills present in both passes and accepts no repeat key. Depending on assembly, the intersection can be empty or pair the wrong images. Explicitly map repeat indices back to the original `(camera_id, file)` before validation and agreement; test the complete shuffled-repeat workflow.

7. **Critical — Missing head predictions can be marked held out.** `common.fit_all_predict()` returns all NaNs for empty or one-class training populations. The proposed flag nevertheless marks every nontraining row held out, even when no prediction exists. Require a non-null prediction when setting `pothole_heldout`, distinguish unavailable evaluation from a losing model, and test entirely empty and one-class Charlotte populations.

8. **Critical — The camera sample-size gate must apply separately to each score.** Thirty eligible cameras do not establish thirty held-out rate or cracking predictions. Applying `MIN_CAMERAS` before score availability filtering can publish a ratio based on only a few cameras. For each score, filter valid predictions and held-out flags first, then calculate sample size, thirds and the `too_few` decision. Add a test with over thirty graded cameras but fewer than thirty usable predictions.

9. **Suggestion — Specify bootstrap multiplicity and undefined-result handling.** Step 5 must duplicate a block’s rows each time that block is sampled; filtering with `isin(sampled_blocks)` would discard multiplicity and produce the wrong interval. Define how draws with insufficient bands or zero best-fifth report rates are handled, report the number of valid draws, and test repeated selections plus an all-zero-report population.

10. **Suggestion — Individually atomic writes do not keep report inputs consistent.** Step 3 replaces reports, boundaries and metadata separately. Failure after replacing reports can leave new reports paired with an old `pulled_at`, which Step 4 then uses for exposure. Stage a versioned bundle and publish its manifest last, or record and verify hashes tying metadata to both parquet files. Test failure between publication steps, beyond P9’s single-file failure case.
