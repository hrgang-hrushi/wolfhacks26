## Step 1. `src/pipeline/helene_dem10.py` (new) and `tests/helene_depth/test_hd_ground.py`

Module docstring in the style of `dem.py`: what it fetches, the output folder, the commands.

Constants: `ROOT = Path(__file__).resolve().parents[2]`, `OUT = ROOT / "data" / "processed" / "dem10_helene"`, `TILE_DEG = 0.1`, `HALO_PX = 3`, `PX_DEG = 1 / 10800`, `RES_TOL = 1e-7`, `SOURCE` (text for the manifest), `TIF` (as `dem.py` L46 with 256 px blocks).

Errors: `class GroundError(RuntimeError)`, `class MissingTile(GroundError)`.

Functions:
- `tile_of(lon, lat)`: integer pair `(floor(round(lat / TILE_DEG, 9)), floor(round(lon / TILE_DEG, 9)))`, vectorised.
- `tile_name(tile)`: `f"t_{ilat:+05d}_{ilon:+05d}.tif"`. `tile_bounds(tile)`: the core box. `fetch_bounds(tile)`: the core box grown by `HALO_PX * PX_DEG` on every side.
- `tiles_needed(lon, lat)`: the sorted unique `tile_of` over the given points. The caller passes every mark and every sampled point of every candidate road (Step 4 `candidates`), so each point that will ever be sampled has its tile by construction. (B10, B11)
- `_fetch(bounds)`: lazy `import py3dep`; `da = py3dep.static_3dep_dem(bounds, 4326, 10)`; returns `(np.asarray(da.values, "float32"), da.rio.transform(), da.rio.crs)`. The only network call; tests replace it.
- `check_reply(arr, transform, crs, tile)`: raise `GroundError` when the array is empty or not 2-D; when no cell is finite; when the CRS is not EPSG:4269; when the grid is rotated (`transform.b != 0` or `transform.d != 0`); when `abs(transform.a - PX_DEG) > RES_TOL` or `abs(-transform.e - PX_DEG) > RES_TOL`; or when the array's extent does not cover the tile's core box plus one cell on every side (so a reply for the wrong place cannot pass). (B8, B6, B12)
- `sha256(path)`: chunked file hash.
- `write_tile(out, tile, arr, transform)`: `rasterio.open(tmp, "w", **TIF, height, width, transform, crs=crs)` (the CRS that `check_reply` accepted) where `tmp = out / (name + ".tmp")`, then `os.replace(tmp, out / name)`; on any exception remove `tmp` and re-raise. Returns the manifest entry `{"sha256", "shape", "transform": [a, b, c, d, e, f]}`. (B5)
- `load_manifest(out)` / `save_manifest(out, m)`: `manifest.json` with `source`, `px_deg`, `halo_px`, `tiles: {name: entry}`; saved through a temporary name and `os.replace`, keys sorted.
- `pull(tiles, out=OUT, force=False, fetch=_fetch, workers=4)`: skip a tile whose file exists and whose sha256 equals its manifest entry (unless `force`); fetch the rest in a `ThreadPoolExecutor(workers)`; in the main thread, for each finished fetch: `check_reply(arr, transform, crs, tile)`, `write_tile`, add the entry, `save_manifest`. A failed tile leaves no file and no entry; the first failure is re-raised after the pool drains. Returns the number fetched.
- `class Ground`: `__init__(self, out=OUT)` loads the manifest (absent: `GroundError`). `_open(tile)`: no entry or no file raises `MissingTile` naming the tile (B4); sha256 differs from the entry raises `GroundError("... does not match the manifest")` (B7); pixel size off by more than `RES_TOL` raises `GroundError("... wrong resolution")` (B6); a stored grid that does not cover the tile's core box raises too; caches `(array, transform)` for at most 16 tiles (oldest dropped first). `sample(lon, lat, tile=None, method="bilinear")`: arrays in, float64 out; groups points by `tile_of` (or uses the forced `tile`, for B2); `col = (lon - c) / a - 0.5`, `row = (lat - f) / e - 0.5`; bilinear from the 2 x 2 cells around `(row, col)`; outside the array or any of the four blank gives NaN (B3). `method="nearest"` returns the cell that holds the point; it exists so the real-data test N6 can compare like with like against the USGS point lookup, and is not used for depths.
- `main()`: `argparse` with `--force`, `--workers`, `--list`. Imports `helene_depth` inside the function, loads the marks, builds the lines, calls `helene_depth.candidates(...)` (Step 4) for the sampled road points, computes `tiles_needed` over those points and the marks, prints the count, calls `pull`, prints tiles fetched and total size.

## Step 3. Stream lines and the level lookup, and `test_hd_profile.py`

- `Line` (a small dataclass): `group`, `x`, `y`, `s` (station, metres), `z` (level), `ids` (tuple of mark ids per vertex).
- `build_lines(marks)`: per group over `draws` marks in order; walk the marks, starting a new vertex when the step from the current vertex's first mark is at least `MERGE_M`, else add the mark to the current vertex; vertex position is the mean position, level the mean level (D7, C5). Returns a list sorted by group.
- `_pieces(lines)`: arrays describing live sub-pieces (D8). For a line segment of length `L` between vertices `k` and `k+1`: if `L <= 2 * REACH_M` one piece covering it; else two pieces, `[0, REACH_M]` from vertex `k` and `[L - REACH_M, L]` up to vertex `k+1`. Each piece carries its end coordinates, the stations and levels of both vertices, `line`, `k`, and four flags: `clamp_lo`, `clamp_hi` (the piece end is a real vertex) and `term_lo`, `term_hi` (that vertex is the first or last of the line). A one-vertex line contributes a zero-length piece with both `term` flags.
- `locate(lines, px, py, chunk=1000)`: for each point and piece, `u` = projection in metres along the piece. `u < 0`: if `clamp_lo` then `u = 0` and the candidate is "at the low vertex", else invalid. `u > len`: likewise with `clamp_hi`. Side distance = distance to the foot. A candidate that was clamped onto a `term` vertex is valid only when the side distance is at most `END_CAP_M` (D8 end rule, C6, C7). The winner is the valid candidate with the smallest side distance not above `SIDE_CAP_M`; ties go to the lower piece index (pieces are ordered by group, then position). Returns a DataFrame aligned with the points: `assessed`, `wse` (linear between the two vertices at the foot's station), `along_m` (station distance to the nearer vertex), `side_m`, `end_rule`, `high` (`along_m <= HIGH_CONF_M` and not `end_rule`), `line`, `v0`, `v1` (`v1 = -1` under the end rule), `group`. Not assessed rows hold NaN and -1.
- `marks_behind(lines, loc)`: the set of mark ids for a located point (`ids[v0]` and, when `v1 >= 0`, `ids[v1]`).

## Step 4. Road points, bridges, depth, per-segment summary, and `test_hd_points.py`

- `segment_points(geom_m, spacing)`: for a LineString of length `L`, `n = max(2, ceil(L / spacing) + 1)` points at `L * i / (n - 1)` via `shapely.line_interpolate_point`; for a MultiLineString, each part in turn; returns `(x, y, part, step_m)` arrays; an empty or missing geometry returns none (D10, D1 to D3).
- `is_bridge(struct_type)`: False when the text matches `culvert|pipe|rcbc|cmp|corrugated|aluminum|multi-plate` (case-insensitive), True otherwise including blank (D12.1, D15 test).
- `load_bridges(path=BRIDGES)`: missing file raises `DepthError` naming it and the command that makes it (`python -m src.pipeline.pull_helene structures`) (D13 test); needs `Struct_Type`, `LONG_DD`, `LAT_DD`; returns EPSG:32119 `x, y` of bridge rows.
- `set_aside(ground, part, step_m, near_bridge, rules=("bridge", "notch", "bank"))`: boolean array. Seeds: `near_bridge` (rule "bridge"); notch (rule "notch"): for `k` in (1, 2), same part on both sides, `ground[i] <= min(ground[i-k], ground[i+k]) - NOTCH_M`. Bank (rule "bank"): from every seed, in each direction inside its part, while the step from `j` to the next point climbs more than `BANK_RISE_M * step_m / 30`: move to the next point and set it aside only if the step beyond it is also that steep; stop at the top or at the part's end. NaN ground never satisfies a comparison (D12).
- `near_bridges(x, y, bx, by)`: `scipy.spatial.cKDTree` nearest distance `<= BRIDGE_M`.
- `band(depth)`: text label from `BANDS_M` (0 gives `dry`).
- `summarise(pts, band_table)`: ties are settled the same way every time: the headline pair is the first pair, in (`part`, `i`) order, that reaches the maximum; `mark_dist`, `conf` and `stream` come from that pair, `stream` being the group of its deeper point (the first point when equal); when dry, `stream` is the most common group among kept points, alphabetical on a tie. `pts` has one row per road point (`seg_id`, `part`, `i`, `depth`, `kept`, `along_m`, `high`, `end_rule`, `group`, `line`, `v0`, `v1`, `aside`). Per segment: neighbouring kept pairs inside a part; `assessed` = at least one pair; headline = max over pairs of the smaller depth (D13, D11 test); `point_max`; `wet_share`; `mark_dist` and `conf` per D14; `stream`; `n_marks` through `marks_behind`; `n_points`, `n_set_aside`; `typical_miss` looked up in `band_table` by `mark_dist` (blank when the band is flagged too few). Returns one row per segment present in `pts`.
- `candidates(lines, seg_geom)`: select candidate segments with a shapely `STRtree` over the live pieces (`predicate="dwithin"`, `distance=SIDE_CAP_M`) after a bounding-box pre-filter in lon/lat, run `segment_points` on each, and return one row per sampled point (`seg_id`, `part`, `i`, `x`, `y`, `lon`, `lat`, `step_m`) plus the count of skipped empty geometries. Used by both `helene_dem10.main` (for the tile list) and `build`, so the two cannot disagree about which points exist.

## Step 5. The error tests and `test_hd_validate.py`

- `hidden_mark_test(marks)`: rows `mark_id`, `group`, `stretch`, `assessed`, `guess`, `miss` (`guess - wse_m`), `along_m`. For each stretch in `HOLD_STRETCHES_M` and each `draws` mark: hidden set = that mark, plus (stretch > 0) every `draws` mark of its group whose station on the full line is within the stretch; rebuild that group's `Line` without them, keep the other lines, `locate` the mark's own position (D17, E1, E2). Poor and Very Poor marks are located against the full lines with `stretch = -1` (E9).
- `miss_stats(miss)`: `n`, `median` and `p90` of the absolute miss, `bias` (median signed) (E3).
- `band_table(hm)`: per band of `DIST_BANDS_M`, per mark the row from the smallest stretch whose `along_m` lands in that band; `n`, `median`, `p90`, `too_few = n < MIN_BAND_N` (E6).
- `boot_range(values, groups, n=BOOT_N, seed=SEED)`: `np.random.default_rng(seed)`; resample the sorted unique groups with replacement, pool their values, take the median absolute value; return the 2.5th and 97.5th percentiles (D20, E8).
- `tape_tests(marks, g10, hm)`: taped = `tape_m` finite and ground finite. (a) `wse_m - g10 - tape_m` over all taped marks; (b) the stretch-0 guess minus `g10` minus `tape_m` over taped `draws` marks with a guess (D18, E4, E5). Each with `miss_stats` plus the correlation.
- `gate_30m(marks, g10, dem30=DEM30, skip=False)`: zero taped marks with finite 10 m ground raises `DepthError` (a gate with no evidence refuses). An absent 30 m file raises `DepthError` unless `skip`, which returns `{"skipped": True, ...}` and still enforces `miss10 <= MAX_TAPE_MISS_M`; otherwise samples the 30 m file at the marks (`rasterio` `sample`), keeps taped marks finite in both, and raises unless `miss10 < miss30` and `miss10 <= MAX_TAPE_MISS_M` (D19, E7, E11).
- `labels_check(per_segment, seg_path=SEG)`: failed share among assessed segments with headline >= 0.3 m and among dry ones, with counts; an absent column or file returns `{"available": False}` (D21).
- Empty evidence is explicit everywhere: `miss_stats` of nothing returns `n = 0` with `None` for the other values; an empty band reports `n = 0`, `too_few = True`, `None`; `boot_range` of nothing returns `[None, None]`; `tripwire` with no finite ground at any line-drawing mark raises; and `pre_checks` raises when the stretch-0 run yields fewer than `MIN_BAND_N` guesses in total (no error number can be stated).

## Risks and how they are handled

- **Venue network drops a tile fetch.** `pull` is resumable and refuses partial tiles; only ports 80 and 443 are needed.
- **The camera fine-tune is running on this Mac.** This work is CPU-light (point sampling and small array maths) and uses no GPU; `pull` uses 4 threads.
- **Memory.** `locate` works in chunks of 1,000 points against at most about 4,000 pieces (tens of MB per chunk). Tiles are opened one at a time and cached; 84 tiles of 4.7 MB is under 0.4 GB if all are held, so the cache keeps at most 16.
- **Mark numbering that doubles back.** The line follows survey order; a stream numbered out of order would fold the line. The hidden-mark test measures the result as it is (pre-plan: 0.41 m overall); streams with a typical miss above 1 m are listed in the validation file for the user rather than re-ordered by a new rule.
- **A bridge not in the list.** The notch rule, the two-point headline and the 15 m stop limit it; the limits section says so.
- **Other chats' files.** All writes go through `_own`; shared inputs are fingerprinted before and after.
- **iCloud sync.** Every file is written to a temporary name and renamed.
