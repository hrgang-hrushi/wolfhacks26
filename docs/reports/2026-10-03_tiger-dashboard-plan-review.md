1. **Critical — The pool constructor will fail at startup.** Step 8 passes `wait=False` to `ConnectionPool`, but that constructor has no `wait` parameter. Use `open=False` followed by `pool.open(wait=False)`, and wire the configured pool timeout explicitly. Add a lifespan test using the actual pool rather than an injected substitute. [Psycopg API](https://www.psycopg.org/psycopg3/docs/api/pool.html)

2. **Critical — Full refreshes can hide replay inserts.** Refreshing through `NULL` can materialize the current or future hour. Real-time aggregation only reads raw rows beyond the materialization watermark; replay rows inserted into already materialized hours remain invisible until another refresh. D12 inserts beyond the latest reading, so it misses this case. Define refresh boundaries compatible with replay and test replay twice in the same hour, including after `--clear`. [Timescale troubleshooting](https://docs.timescale.com/use-timescale/latest/continuous-aggregates/troubleshooting/)

3. **Critical — The aggregates lose information needed to exclude replay rows.** `bool_or(replay_of IS NOT NULL)` cannot separate original and replay contributions when both occupy the same camera/station/hour. Filtering out replay-marked aggregate rows would also remove real observations; retaining them contaminates `/api/alerts/peaks`. Preserve separate contributions or compute replay-excluding results from raw rows. Also exclude replay consistently from verify’s time ranges and summary comparisons, not just its counts. Test a mixed original/replay bucket.

4. **Critical — The local-database guard can connect remotely.** Checking `host` and `conn.info.host` misses `hostaddr`: libpq can retain `host=localhost` while connecting to a remote `hostaddr`. This exposes the destructive test setup and schema sweep to a remote database. Validate all effective connection parameters before connecting and check the actual server address before mutations. Add a conflicting `host`/`hostaddr` regression test. [PostgreSQL connection parameters](https://www.postgresql.org/docs/17/libpq-connect.html)

5. **Critical — Sanitizing HTTP errors does not sanitize pool logs.** The service bypasses `config.connect`, and psycopg’s background pool workers log connection exceptions directly. A refused connection can therefore expose connection details in stderr even when the response is clean. Sanitize that logging path and extend S10 to start the actual service against failed network and login connections, capturing background logs as well as responses. [Psycopg pool source](https://github.com/psycopg/psycopg/blob/master/psycopg_pool/psycopg_pool/pool.py)

6. **Critical — The streamed CSV’s ownership and failure behavior are unspecified.** `write_risk_csv(rows, fh)` writes to a file handle; it is not the iterator that `StreamingResponse` expects. The server-side cursor also needs its connection and transaction to remain open throughout iteration and close on cancellation. Define the adapter and cleanup explicitly. Acquire the connection and execute the query before sending headers so initial database failures can return 503; test disconnects and failures during iteration. [Starlette streaming responses](https://www.starlette.dev/responses/)

7. **Critical — Reloads can expose inconsistent generations.** The plan acknowledges that summaries remain stale after the COPY transaction commits, but only requires `/api/summary` to report “loading.” `/api/road` and `/api/alerts` can consequently combine new road/camera rows with old aggregates after a refresh failure. Define a loading guard for every database-backed route and check it in the same consistent read transaction as the query. Extend D4/A16 to exercise these routes after COPY and after a partial refresh.

8. **Critical — An hour-old schema is not necessarily abandoned.** Step 2 can delete another active test session’s schema once that session runs longer than an hour, including a session-scoped `real_schema`. Age alone does not establish ownership or inactivity. Remove automatic sweeping, or require a verifiable lease/lock showing that the owning session has ended. Test that an old but active schema survives cleanup.

9. **Suggestion — Alert timestamps need a defined meaning.** `sensor_hourly` retains no reading timestamp, although D14 requires each alert’s reading time. For cameras, independently taking maximum probability, maximum depth, and latest time can associate a peak value with a different observation’s timestamp. Preserve the necessary observation times or label values explicitly as hourly maxima with a separate latest-observation time. Test an early threshold crossing followed by a later dry reading.

10. **Suggestion — Fingerprints can describe different bytes from those loaded.** `build_all` reads shared files and fingerprints them afterward. Another pipeline can replace a file between those operations, leaving a manifest that matches disk while the database contains older data. Compare fingerprints before and after building and refuse changes, or build from an immutable snapshot. Test a source replacement during the build.

11. **Suggestion — The documented `$PY` commands are not executable as written in the supplied zsh environment.** Zsh does not split a scalar containing a command and arguments by default, so `$PY -m ...` attempts to execute the entire string as one command name. Use a shell function, an argument array, or spell out `env PYTHONPATH=... "$MAINPY"` in the commands.
