## Problem

Each road has one 128 x 128 aerial photo and the road is about 12 pixels wide in it. The image model can latch onto accidents of that one photo. Augmentation (showing it flipped, turned, slightly brightened and shifted copies) is the standard remedy, but the research run found no checked evidence that it helps on photos like these. The landed fine-tune loop uses flips only and has never been run. Nobody has measured, on held-out map squares, whether augmentation changes the result.

Two things block a measurement today: only 50 photos are on this machine (the venue link fetches about 3 a second), and there is no switchable augmentation or view-averaging code.

## Decisions

- **D1 New files only.** No existing file is edited: not `src/pipeline/*`, `train_vit.py`, `train_tabular.py`, `final_ablation.py`, `pyproject.toml`, `uv.lock`, `README.md` (named `readme` when this was planned) or `PLAN.md`.
- **D2 Labels and folds are inputs.** `vision_data.load_table` reads `data/processed/segments_targets.parquet` and refuses it unless it has `seg_id` (unique, non-null), `y_rate`, `y_crack`, `mid_x`, `mid_y`, `split_block`, `fold`, with `split_block == f"{floor(mid_x/5000)}_{floor(mid_y/5000)}"` and `fold == crc32(split_block) % 5` on every row. The pre-hardening file fails this gate.
- **D3 Toolbox** (`src/model/augment.py`, numpy only, chips are `(4,128,128)` uint8 in band order R, G, B, NIR):
  - `view(chip, k)`, k in 0..7: the 8 symmetries of a square. `k < 4` is k quarter turns; `k >= 4` is a left-right flip then `k - 4` quarter turns. `inverse_view` undoes it.
  - `gain(chip, g)`: multiply all four bands by the same `g`, round, clip to 0..255. Allowed range 0.8 to 1.15 (tightened from 1.25 at execution; see Deviations).
  - `contrast(chip, c)`: stretch all four bands around one shared grey level (the mean over all bands). Allowed range 0.8 to 1.25.
  - `shift(chip, dx, dy)`: move all four bands together by whole pixels, at most 4, filling the exposed strip by repeating the edge.
  - `ndvi(chip)`: `(NIR - red) / (NIR + red)` from bands 3 and 0 as float32, 0 where both are 0. `ndvi_stats(chip)` gives `im_ndvi_mean`, `im_ndvi_std`, `im_impervious_frac` (share of pixels with NDVI below 0.1), `im_bright_var`. NDVI is always computed from the original chip, never an augmented one.
  - Presets: `NONE`; `FLIPS` (views 0, 2, 4, 6: the four results of independent left-right and up-down flips, equal to today's `train_vit.py`); `FULL` (all 8 views, gain and contrast each drawn from 0.9 to 1.1, shift up to 4 px each way; narrowed from 0.85 to 1.15 at execution, see Deviations).
  - `ALLOWED_OPS = ("view", "shift", "gain", "contrast")`. No hue or saturation change, MixUp, CutMix, random erasing or RandAugment.
- **D4 Randomness.** `random_augment(chip, rng, preset)` uses only the generator it is given. The generator for a sample is `default_rng([seed, epoch, index])`, so the result does not depend on the number of loader workers or on global random state.
- **D5 Same model and preprocessing as the landed code.** The model is `train_vit.Net`, imported. Model input is bands 0 to 2, cropped `[1:127, 1:127]`, divided by 255, as in `train_vit.DS`. A parity test compares the two.
- **D6 Frozen comparison.** Embed every chipped road with the frozen backbone. Arm `1view` uses view 0. Arm `8view` uses the mean of the 8 view embeddings. Probe, per fold, fitted on the other four folds only: standardise, then `Ridge(alpha=1.0)` for rate, `LogisticRegression(C=1.0)` for cracking, and `LogisticRegression(C=1.0)` for Helene failure on rows inside the zone. Settings are fixed in advance; nothing is tuned.
- **D7 Fine-tune comparison.** Arms `none`, `flips`, `full`. Optimiser, learning rates, weight decay, batch size (128, a setting) and loss are those of `train_vit.py`. 6 epochs, fixed; the last epoch is scored, never the best one. Each fold model scores its own held-out fold once with one view and once averaged over 8 views (rate outputs averaged; cracking logits averaged). Held-out metrics per epoch are logged for reading, not for choosing. Jobs are explicit (arm, seed, fold) triples. Full schedule: 3 arms x 5 folds x seeds 0 and 1, plus one shuffled-label control. Reduced schedule, used only if the timing gate requires it: seed 0 for every arm and fold, seed 1 on fold 0 for each arm, plus the control. The seed spread is measured on matched runs: every fold in the full schedule, fold 0 in the reduced one. A fold with fewer training roads than one batch is refused, and every epoch must take at least one optimiser step.
- **D8 Metrics.** Rate: MAE and Spearman, plus the do-nothing MAE (training-fold median). Cracking: AUC-PR and prevalence. Flood (frozen only): precision at 50 and AUC-PR inside the zone. Each per fold and pooled. Differences between arms: per-fold paired differences, and a 95% interval from 1,000 bootstrap resamples of whole blocks.
- **D9 Controls.** A shuffled-label run for the probe and for one fine-tune fold must score at chance. A difference is called real only if its interval excludes 0 and, for the fine-tune, it exceeds the seed-to-seed spread.
- **D10 Same roads in every arm.** Roads whose chip is missing or more than 5% blank (all four bands 0) are excluded from every comparison arm and counted. Each result stores a hash of its road list; comparing results with different hashes is refused. Embeddings and NDVI statistics are computed for every valid chip before that exclusion, and carry `blank_frac` and `usable` columns.
- **D11 Outputs.** Everything is written under `data/processed/vision/` through a temporary file and rename: frozen results in `frozen/`, fine-tune results in `finetune/`, by-products at the top level. Each result carries the code hash, the table hash, the road-list hash and a fingerprint of the pretrained backbone weights (a fine-tune job also records its full starting weights). The table hash covers every column this change reads: `seg_id`, `fold`, `split_block`, `mid_x`, `mid_y`, `y_rate`, `y_crack`, `y_helene_failed`, `in_helene_zone`. Each fine-tune job writes a completion record last, holding its settings, those hashes and a checksum of each file it wrote; on resume a job is skipped only if that record validates in full. Nothing is written to `segments.parquet` or `vit_frozen.parquet`, and model code never writes to `data/chips/`.

## Failure modes and tests

**Toolbox** (`tests/vision/test_augment.py`)
- A1 the 8 views are pairwise different on a lopsided chip. A2 the same check finds only 1 distinct view on a constant chip (the test has teeth). A3 shape and dtype kept. A4 each band keeps its own sorted pixel values (no band mixing, no resampling). A5 corner markers land in the 8 expected arrangements. A6 `inverse_view` restores the original for every k. A7 no operation modifies its input. A8 `view`, `gain`, `contrast` and `shift` always return a new contiguous array that owns its data and is accepted by `torch.from_numpy`, including at identity settings (view 0, gain 1, shift 0). A9 k outside 0..7 raises.
- A10 gain scales all bands alike and leaves NDVI within 0.02 on unsaturated pixels. A11 a per-band gain helper fails the A10 check. A12 no wrap-around: 250 times 1.15 is 255; no pixel gets darker when brightening or brighter when dimming. A13 gain outside 0.8..1.15 raises. A14 at the strongest allowed gain, and at `FULL`'s strongest gain and contrast together, under 2% of pixels in the 50 real chips newly reach 255, overall and in every band. A15 gain 1, contrast 1, shift 0 and view 0 return equal arrays.
- A16 contrast leaves a constant chip unchanged and uses one grey level for all bands. A17 contrast outside its range raises.
- A18 a marker moves by exactly (dx, dy) in all four bands. A19 the exposed strip repeats the edge and does not contain the opposite edge. A20 a shift above 4 raises.
- A21 NDVI is 0.5 for red 50, NIR 150; float32. A22 it matches the band-3, band-0 formula and differs from the same formula on other bands. A23 all-zero pixels give 0 with no warning. A24 red above NIR gives a negative value; all values within -1..1. A25 `ndvi_stats` keys and ranges.
- A26 same (seed, epoch, index) gives the same output. A27 a different index or epoch gives a different output. A28 global random state has no effect. A29 800 draws use all 8 views roughly equally; `FLIPS` uses only views 0, 2, 4, 6; `NONE` is the one documented fast path: it returns the input object itself and records 0 changes. A30 `ALLOWED_OPS` is pinned and no banned name exists in the module. A31 3-band, channels-last, float and non-square inputs raise. A32 `FULL` changes the chip in at least 95% of draws and records what it did.

**Data** (`tests/vision/test_vision_data.py`)
- D1 a table without `fold` or `split_block` is refused, with a message naming `train_tabular`. D2 a fold that is not `crc32 % 5` is refused. D3 a block that does not match the 5,000 m rule is refused (4,999 m and 5,001 m cases). D4 duplicate or null `seg_id` is refused. D5 a good table is accepted with row order kept. D6 every block maps to one fold.
- D7 chip paths come from `chips.chip_path` and are unique across all real roads. D8 a wrong-shape or wrong-type chip raises naming the road; `.npy.tmp` files are ignored. D9 a chip more than 5% blank is flagged and excluded.
- D10 model input equals `train_vit.DS` output for the same chip. D11 model input is bands 0, 1, 2 in order, in 0..1, shape (3,126,126).
- D12 scoring reads are repeatable; training reads with `FULL` differ between epochs; with `NONE` they equal the scoring read. D13 with 2 loader workers the augmentation records equal those with 0 workers.
- D14 every view and 20 random copies of a road carry that road's fold; training and held-out roads never overlap, for all 5 folds. D15 each labelled road is held out exactly once. D16 the road-list hash is stable and differs when the list differs. D17 the cross-fold neighbour count is 1 for a pair 50 m apart in different folds and 0 at 100 m. D18 the code hash is stable and changes when a file changes. D19 a failed write leaves no partial file, and a path outside `data/processed/vision` is refused. D20 on the real table: 112,443 rows, 77,422 rate labels, 68,349 cracking labels, 10,766 positive, each fold 15% to 25%. D21 changing any column the table hash covers (including the two Helene columns) changes the hash.

**Metrics** (`tests/vision/test_vision_metrics.py`)
- M1 perfect predictions give MAE 0 and Spearman 1. M2 constant predictions give NaN Spearman, not an error. M3 random scores give AUC-PR within 0.03 of prevalence. M4 precision at 50 on a hand example. M5 the do-nothing MAE uses training-fold medians only. M6 per-fold and pooled values agree with hand calculation. M7 identical arms give a difference of exactly 0. M8 a planted gain gives an interval that excludes 0. M9 the bootstrap resamples whole blocks and repeats with the same seed. M10 every number in the generated report equals the results file. M11 results with different road-list, code or table hashes are refused.

**Frozen** (`tests/vision/test_vision_frozen.py`, with a small stand-in model)
- E1 one embedding per road, in order, none dropped. E2 a chip embeds the same alone and in a batch. E3 a road's 8-view mean equals the mean of its own 8 view embeddings and differs from another road's. E4 the 8-view mean is unchanged when the input is turned or flipped. E5 the 1-view and 8-view embeddings differ on a lopsided chip. E6 two passes are identical and no gradients are kept.
- E7 shuffling a held-out fold's labels, or corrupting its features, does not change the model that scores it. E8 on synthetic data with a planted signal, real labels score above 0.5 Spearman and shuffled labels below 0.1. E9 each labelled road is predicted once. E10 both arms carry the same road-list hash. E11 (box) the real weights give 384 numbers per road on the GPU and the weights fingerprint is recorded. E12 a fold with no labelled training rows, or one training class, is skipped: its predictions stay missing and the report counts it. E13 a flood subset with no rows gives NaN metrics, not an error. E14 NDVI statistics and the two `vit_frozen`-format files have one row per valid chip, blank ones included, with `usable` false for those; the reduction equals `PCA(16, random_state=0)` on the same embeddings. E15 running the frozen runner and then the fine-tune report on fixtures leaves both `frozen/` and `finetune/` result sets intact.

**Fine-tune** (`tests/vision/test_vision_finetune.py`, with a small stand-in model on CPU)

F3 changes applied: 0 for `none`, above 0 for `flips` and `full`. F4 the arm settings differ only in the preset. F5 training and held-out roads are disjoint and each prediction's fold is its model's held-out fold. F6 the saved predictions are the last epoch's. F7 a NaN loss raises and writes nothing. F8 one step changes both backbone and head weights. F9 the loop drives the loss down by 80% on 32 samples. F10 the same seed gives identical predictions; another seed differs. F11 the 8-view prediction equals the mean of the per-view predictions and is unchanged when the input is turned. F12 output columns, one row per road, written under the output root, with every hash. F13 the schedule is refused when the projected cost exceeds the money left, or the projected time (model start-up, training, per-epoch scoring, 8-view scoring, writing, the report) exceeds the time left minus a 20-minute reserve for copying results and teardown. F14 a flood target is refused. F15 (box) the real model memorises 32 real chips at batch size 8 and the timing of each part of a job is recorded. F16 a fold with fewer training roads than one batch is refused, and a completed epoch with zero optimiser steps raises. F17 the reduced schedule keeps seed 0 for every arm and fold and adds seed 1 on fold 0 only; the runner executes exactly the jobs listed. F18 the seed spread uses matched runs only. F19 resume skips a job whose completion record validates, and reruns it when the epochs, the shuffled flag or any hash differs, or when a listed file is missing or altered.

### Deviations from the plan

1. **Brightness limits tightened (D3).** Test A14, run on the 50 real chips, showed that a gain of 1.25 newly saturates 6.0% of pixels and 20% of the near-infrared band, and that gain and contrast both at 1.15 saturate 3.2% (11% of near-infrared). The allowed gain range is now 0.8 to 1.15 (0.26% saturated, 0.69% of near-infrared), and the `FULL` preset draws gain and contrast from 0.9 to 1.1 (0.23% at the strongest draw). A14 now checks the gain limit and `FULL`'s strongest combined draw, overall and per band.
2. **Offer ids change between listing and renting.** `box.py rent` takes the first offer that still passes the filter instead of a fixed id (`rent_first`, `OfferGone`). The first attempt failed for this reason with nothing rented.
3. **Network check before renting (new, test C24).** `rent` now refuses when outgoing high ports are blocked, so a box that cannot be reached is never paid for.
4. **Instance label and scoped teardown (new, test C25).** The box is labelled `image-augmentation`; destroy, stop and start act only on this change's own instance id, because another chat may rent from the same account.
5. **Self-stop tests added (C23).** A box without its own key, one that does not stop itself, and one that does not restart are each abandoned; a working self-stop restarts and arms the watcher.
6. **Training rows.** A fold's model trains on usable roads that have at least one label. Roads with neither label contribute nothing to the loss in `train_vit.py` either; leaving them out saves about a quarter of the compute.
7. **`ViewDataset` serves a fold through a row list** instead of a copied array, and keys each random draw by the road's row, so a road's draw does not depend on which fold is held out.
8. **Test helpers live in `tests/vision/vision_helpers.py`**, imported by name, so the tests do not depend on which `conftest.py` pytest loads first.
9. **The deadline watcher is installed by the box's own start-up script** (`--onstart-cmd` at creation), so it runs from first boot and again after every restart, with no window in which a rented box is unwatched. `rent` confirms it over SSH before returning (the recorded pid must exist and be the watcher) and starts it if it is missing; a box whose watcher cannot be confirmed is destroyed at rental, or stopped after a restart. At the deadline the watcher repeats the stop call every minute for as long as the box is up, because the vast.ai CLI exits 0 even when the API refuses and so cannot report a failed stop. It uses no tools the image might lack.
10. **Every failure after the box exists destroys it.** `rent` wraps everything after the instance id is saved, including an interrupt; a dropped status poll is ridden out; a hung command is reported like any other failure; an instance that is already gone counts as destroyed.
11. **The teardown gate checks the files, not timestamps.** Without `--force-discard`, teardown refuses while any job is still running, when the box holds no results, or when any result file on the box is missing or different on this machine (size and SHA-256).
12. **`pull` writes only into `data/processed/vision` or `data/chips`.** Results replace older results; in `data/chips` an existing file is never replaced, whatever the flag. Remote folder names and job names are validated and quoted.
13. **The key scan is wider**: case-insensitive, more file names (`.env*`, `*.key`, `*credentials*`), more patterns (generic `key = value` secrets, GitHub and AWS token shapes), and every non-binary file is read.
14. **Spend state lives outside the repository** (`~/.config/hack-ncsu-cloud`), so the cap holds from any checkout. Offers are priced with the 100 GB disk actually rented, and the billed price from the instance record is used when it is higher.
15. **The photo checks are commands**: `box.py identity` (the 50-photo comparison; a mismatch destroys the box), `box.py trial` (three trials of 500; too slow destroys the box), `box.py census` (the fetch contract; a failure stops the box and keeps the photos), `box.py county-chips`. The chips log is read from its last run only.
16. **A failed install no longer destroys the box.** `setup` reports the install failure with the log tail and leaves the box up for the fallback install; only a GPU that does not work destroys it.
17. **The fine-tune report validates every record it reads.** A job, a seed-1 run or the control whose record does not match the current code, labels, roads, weights or settings, or whose result file is missing or altered, makes the report refuse. A missing control also refuses.
18. **No seed spread, no verdict.** A fine-tune difference is called real only if its interval excludes 0 and it exceeds the seed spread; with no matched seed-1 run it is printed "not judged (no seed spread)". An interval from fewer than 30 blocks is never treated as excluding 0.
19. **Report additions**: the do-nothing error and cracking prevalence per fold, and each control's "at chance" verdict against the AC5 thresholds, computed by the runner.
20. **Smaller changes**: the weights fingerprint in a job record is the pretrained backbone's (each job's full starting weights are recorded as `start_weights`); `--time-only` measures the write and the chip load instead of assuming them; the report is budgeted 10 minutes and runs its bootstraps in parallel, and reads a saved chip index instead of reloading the chips; `--jobs`, `--shuffled-control` and `--report` run in one invocation; the shuffled control permutes labels among all usable labelled rows and is scored against the permuted labels; overlapping chips across folds are counted with a square, not a circle; a fold stored as text or as a fraction is refused; `shift` refuses a non-integer.

    - The speed trial, the identity check and the fetch census no longer destroy or stop a good box by mistake: a rerun trial that had nothing left to fetch raises; a photo that failed to download is retried and never condemns the box (only differing pixels do); asking for the census while the fetch runs is just an error.
    - A job with no exit status and no process counts as dead, not running, so it does not block teardown; what it left is still checked file by file. A stopped box past its deadline can be started with `start --grace` for 20 minutes to copy results off (the watcher allows it); new jobs are refused past the deadline.
